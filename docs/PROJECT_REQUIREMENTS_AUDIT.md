## 1. Executive Summary & Architecture Clarification

The Forge IDE repository is built as an **Electron 35 + React 19 + Monaco Editor + Go Daemon (`forge-daemon`)** monorepo.

Any proposal or summary describing a "GoCodium" architecture using **Wails + embedded VS Code Web workbench + Go AI router** was an **unverified theoretical proposal** that does not reflect the working repository. Specifically:
1. Neither `wails` nor `bun` is installed on this evaluation machine (`which wails` and `which bun` both returned not found).
2. The working codebase does not contain Wails or the VS Code Web workbench.
3. The actual working implementation uses a high-performance, compiled Go daemon (`services/forge-daemon/bin/forge-daemon`) communicating over line-delimited JSON-RPC 2.0 stdio with an Electron desktop shell and React/Monaco renderer.

Below is the exhaustive, requirement-by-requirement audit matrix for all 15 core architectural and functional areas.

## 3. Verification of "GoCodium" Claims

In the table below, each specific claim from the previous proposal is audited against concrete technical, legal, and operational facts:

| Claim | Status | Technical, Legal & Operational Reality |
|---|---|---|
| **VS Code Web Workbench can easily be embedded in a Go/Wails app** | **UNVERIFIED & MISLEADING** | The full VS Code Web workbench is not a standalone npm component; it is an extensive build of `microsoft/vscode` requiring custom web asset hosting, WebSocket server daemons, and complex worker routing. Distributing it inside Wails would require maintaining a massive downstream fork of VS Code, defeating the lightweight goals of Forge. |
| **VS Code source and assets can be redistributed under intended branding** | **LEGALLY RESTRICTED** | While the core source code of VS Code is MIT licensed, Microsoft's official logos, branding, and marketplace access are strictly proprietary. Official Microsoft Marketplace access is prohibited for third-party forks by Microsoft terms; forks must use Open VSX. Furthermore, proprietary Microsoft extensions (such as the official C/C++ extension and C# Dev Kit) are forbidden from running in non-Microsoft IDEs. |
| **Extension host communicates seamlessly with workbench in Go/Wails** | **UNVERIFIED** | VS Code Web uses a browser Web Worker extension host that cannot execute Node.js APIs (`child_process`, `net`, `fs`). To support real language servers and terminals, a separate Node.js server process is still required. A pure Go backend cannot replace the Node.js extension host without polyfilling hundreds of VS Code internal APIs. |
| **Commercial AI Providers (e.g. GitHub Copilot) can be freely embedded** | **LEGALLY RESTRICTED** | The official GitHub Copilot extension has strict licensing terms limiting use to official Visual Studio Code and approved editors. Unauthorized reverse-engineering of Copilot authentication tokens in a custom IDE violates GitHub Terms of Service. However, local-first Ollama models and direct OpenAI/Gemini REST API keys are 100% legal and supported. |
| **Terminal resizing and signals work out of the box in pure Go** | **PARTIALLY TRUE / COMPLEX** | While Unix has `creack/pty`, Windows terminal emulation requires complex ConPTY bindings. Electron's `node-pty` has a 10-year battle-tested track record handling winpty/ConPTY and POSIX pseudo-terminals cleanly. |
| **Claimed Memory: 85 MB Wails / 35 MB Electrobun** | **UNVERIFIED ESTIMATE** | These numbers were speculative estimations from external marketing materials. Neither `wails` nor `bun` is installed on this Apple M5 evaluation machine. Real measurements on this machine show that the Go daemon consumes only **5.61 MB idle / 9.97 MB active**, while Electron's memory is dominated by the Chromium renderer (~140-170 MB). |

1. **The Go daemon (`forge-daemon`) is real, compiled, and benchmarked at 9.30ms cold boot and 5.61MB idle RSS.**
2. **The Electron desktop shell provides rock-solid PTY terminals, native file dialogs, and Monaco Chromium compatibility.**
3. **The React UI provides an authentic CodeEdit/VS Code aesthetic with 2026 Dark Theme and Material Icon Theme.**
4. **All 14 functional flow tests pass cleanly.**
5. **The repository has zero deleted user files and clean branch separation.**
